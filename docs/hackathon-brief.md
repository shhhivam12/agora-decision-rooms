# Verified hackathon brief

Source: [Agora Voice AI Hackathon on Commudle](https://www.commudle.com/communities/ai-mobile-coders/hackathons/voice-ai-hackathon)

## Confirmed constraints

- The final project must be a mobile application or mobile-first experience.
- Android, iOS, Flutter, React Native, and other mobile frameworks are allowed.
- Agora Conversational AI must be a meaningful part of the real-time voice experience.
- There is one open innovation track and no fixed problem statement.
- Other models, APIs, tool calling, MCP, RAG, maps, sensors, and device capabilities may be used.
- The project should go beyond adding a microphone button to a chatbot.
- Evaluation factors include innovation, mobile experience, meaningful real-time Voice AI, technical execution, user experience, and real-world potential.
- The expected submission package includes a working mobile application or prototype, source repository, README, setup instructions, short demo video, problem/solution description, and technology/integration details.
- Participation is individual.
- Existing libraries and reusable components are allowed, but meaningful hackathon work and significant pre-existing work should be disclosed.

## Implications for Agora Decision Rooms

- The live multi-participant room should be the center of the demo, not a text workflow with optional speech.
- At least one external action must produce verifiable output.
- The mobile UI should expose interaction that matters during a call: presence, speaking state, constraint cards, voting, approval, and receipt status.
- Reusing Agora's official starter is appropriate, but the submitted experience must clearly extend it.
- Claims in the README and demo must distinguish live integrations from deterministic fallback data.
